# Outward App Overview

Outward App is a Windows desktop GUI for a system connection (TUN or Windows user proxy) and independent local HTTP/SOCKS5 windows powered by `sing-box`. Users assign saved server profiles to connections and optionally open Chrome or Edge through each window's own SOCKS5 port. Either system mode and several proxy windows can run together. The Windows implementation exists; real privileged TUN acceptance remains pending (see `docs/validation/system-vpn-and-connection-windows.md`). Android/iOS are future clients, not implemented platforms.

Use this overview before broad source exploration. Read only the files relevant to the current request after this unless the task asks for a fresh full audit.

## Main Shape

- Runtime: Python 3.11+, PySide6 GUI.
- Entrypoint: `outward_app/__main__.py` calls `outward_app.ui.app.run`.
- UI app setup: `outward_app/ui/app.py` creates `QApplication`, installs application-wide pointer cursors from `ui/widgets.py` for enabled interactive controls and popup actions, sets the visible app name to `Outward App`, initializes the default Graphite ThemeManager, loads `outward.ico`, opens `MainWindow`. The stored theme is applied before the content is built/shown.
- Runtime data lives in `%LOCALAPPDATA%\OutwardApp`; if `LOCALAPPDATA` is absent, it falls back to `~/.outwardapp`.
- Runtime files: `profiles.json`, `settings.json`, versioned `connections.json`, per-window `sessions/<id>/config.json` and `sing-box.log` (bounded rotation), the managed `bin/sing-box.exe`, downloaded update installers and stable-ID browser profile directories. Legacy files/browser directories remain migration inputs. First migration backs up profiles/settings without deleting originals.
- System service: separate protected onedir `OutwardVPNService.exe` and sing-box in `%ProgramFiles%\OutwardAppVPN`; installation owner manifest and private runtime/logs in `%ProgramData%\OutwardAppVPN`. Install/update is explicit, with UAC; the GUI and local windows run without administrator rights. Do not test installation or alter host routes as a side effect of ordinary UI tests.
- App version is resolved by `outward_app/version.py`: frozen builds read the Windows file version from the executable first, then fall back to bundled/source `VERSION`.
- Visual assets: `assets/outward.png` for in-app avatar/logo and `assets/outward.ico` for window/tray/installer icons. Both are bundled by `OutwardApp.spec` along with `VERSION`.

## Core Modules

- `outward_app/core/system_proxy.py`: pointer-safe WinINet per-connection option snapshots (manual/PAC/autodetect), owned compare-before-restore leases, atomic `system-proxy.json` in app data, and an independent `--system-proxy-watchdog <token>` helper. The helper verifies parent PID/creation time, acknowledges readiness with a named event, waits for parent exit or cooperative stop, and serializes recovery with a path-scoped named mutex. Startup also recovers abandoned leases. It never changes WinHTTP or restores over another application's settings. `SystemProxyManager` keeps listeners alive if restoration fails so cleanup can be retried.
- `outward_app/paths.py`: centralizes source, bundled, asset, app data, config, log, profiles, and settings paths. It handles PyInstaller via `sys.frozen` and `_MEIPASS`.
- `outward_app/version.py`: displays the runtime app version from the frozen executable file version or the bundled/source `VERSION` file.
- `outward_app/core/models.py`: `ConnectionProfile`, `AppSettings`, `RuntimeState`, `SavedConnection` and versioned `ConnectionCollection`. Stable IDs/numbers separate server profiles, saved connection intent and live runtime state. Missing legacy profile metadata remains valid.
- `outward_app/core/connections.py`: protocol-aware parsing and metadata. It detects and parses VLESS links, Shadowsocks `ss://` links, and WireGuard config text, returns `ParsedConnection`, provides protocol labels, and masks secrets in connection errors.
- `outward_app/core/countries.py`: provides all country codes/names from Qt `QLocale`, country-code normalization, and fallback country guessing from profile names/remarks/servers. `outward_app/ui/country_flags.py` supplies local SVG icons for profile badges and the country picker, with a neutral globe for unknown countries or missing assets. Flags and their MIT attribution live in `assets/flags` and are bundled by `OutwardApp.spec` with QtSvg support; no runtime downloads are needed.
- `outward_app/core/storage.py`: atomic UTF-8 JSON writes with a process lock, explicit idempotent migration into connections, backups and rejection of unknown connection schemas. Profiles remain `{"profiles": [...]}`; new profiles are inserted at the top.
- `outward_app/core/updater.py`: checks GitHub Releases for `LikeBench-dev/outward-app`, compares release tags with the current app version, selects Windows installer assets, extracts optional SHA256 values from release notes or checksum assets, downloads installers to the runtime `updates/` folder, and verifies checksums when present.
- `outward_app/core/vless.py`: parses VLESS links into dicts used by the protocol layer. It tolerates `vless\://`, missing `@` after UUID, alternate query names such as `pbk/public_key`, `sid/short_id`, `sni/server_name`, `fp/fingerprint`, and loose query tails after `type=...`. It requires scheme `vless`, UUID, server, port, and Reality public key.
- `outward_app/core/singbox.py`: shared protocol generation plus `build_session_config` for proxy/TUN, per-manager config/log paths, config check, native Windows listener discovery, sanitized bounded logs and owned-process stop. `windows_process.py` assigns kill-on-close jobs. Only verified legacy manifest entries qualify for legacy cleanup; no blanket process/config-path sweep.
- `outward_app/core/sessions.py`: Qt-free coordinator with port ownership, per-session generation/cancellation locks, connection workers, a separate 4-worker ping pool and bounded reconnects. `network.py` separates TLS-verified route checks from TCP ping to the profile server (physical interface, DNS/TLS/HTTP excluded). Ping is queued immediately on connection and about every 5 seconds, with bounded/cancellable DNS and stale-result guards; failed ping cannot reconnect a VPN. WireGuard retains a separately labelled HTTPS duration. Startup probes retry in place up to three times; system health needs two failed external probes before recovery, while process/route loss acts immediately.
- `outward_app/core/vpn_service.py`, `vpn_pipe.py`, `vpn_client.py`, `vpn_install.py`: native SCM service, restricted JSON named pipe (owner ACL, local clients, server PID verification), lease/heartbeat watchdog, protected installation and fixed-path TUN config generation. The service accepts supported profiles, not arbitrary configs/commands/paths. Full crash-proof kill switch is outside the current scope.
- `outward_app/core/browser.py`: finds Chrome/Edge and opens the configured site with `--proxy-server=socks5://127.0.0.1:<port>` and optional `--disable-extensions`. Profiles follow connection IDs; existing legacy directories are reused in place. Live browser port bindings prevent cross-window reuse. Port changes require restarting an already-running browser profile. Missing supported browsers produce a visible error; no direct-browser fallback.
- `outward_app/core/autostart.py`: manages the per-user Windows startup entry under `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` for the independent `launch_on_startup` setting. Frozen builds register the app executable; source runs register `python -m outward_app`; both add `--autostart` so manual launches do not connect automatically. GUI startup refreshes the registration to migrate older commands.

## Supported Protocols

- VLESS: supported through existing VLESS/Reality parser and a `vless` outbound tagged `proxy`.
- Shadowsocks: supported through `ss://` parsing and a `shadowsocks` outbound tagged `proxy`.
- WireGuard: WireGuard config text is parsed and emitted as a modern `wireguard` endpoint tagged `proxy`. The old WireGuard outbound is intentionally not used because newer `sing-box` versions removed it.

## UI Flow

- System mode: `SavedConnection.system_mode` is `tun` by default for legacy data or `proxy`. `ui/system_mode.py` supplies the left-aligned two-segment selector between the header and metrics, with no explanation on its right. Changes save immediately while offline/error with no manager retained, and are blocked while active. Service setup is shown only for TUN. Proxy mode uses its own HTTP/SOCKS listeners under `sessions/system`, allocated independently of windows; Windows proxy settings are applied only after an HTTPS probe succeeds and restored before listeners stop. Health checks stop without reconnect if another program changes the proxy. System traffic combines the service-owned `system` total with locally recorded `system-proxy` usage; local proxy logs use the system session log rather than service IPC. See `docs/validation/system-proxy.md` and `capture_system_mode.py` for validation limits.
- Proxy windows use 260px-wide cards with content-driven height in a wrapping grid (`ui/connection_card.py`): three across at 1100px, two at 900px. No forced square height/bottom spacer; long protocol names wrap. Their profile flag is grayscale while off and colored only after connection, with country metadata snapshotted into `RuntimeState`. Window status words/dot are hidden; connection/browser errors use a small Qt-painted warning triangle beside the title with sanitized hover/keyboard-focus tooltips, without expanding the card. System messages and non-error window captions remain inline. Windows and system share the top-right `PowerButton`: gray off, green connected, cancellable rotating indicator while connecting. Its glyph uses the floating-point frame center and symmetric bounds. The system card has a two-tier layout: title/menu/power on top and profile flag/name/protocol, latency, session and traffic as four aligned groups below. Its repeated app logo and status dot are removed; the power icon carries routine state and adds a green border and subtle success surface when connected. Profile flags in the system card retain their colors while offline.
- `core/traffic.py` reads authenticated loopback Clash API cumulative upload/download byte counters. Each process gets a random port/token. `SessionController` samples windows on its separate traffic pool about every second and before stopping; `VpnBroker` owns system sampling/history and exposes only a monthly total over owner-checked IPC `traffic`. `traffic.json` beside connections stores per-window calendar-month totals/checkpoints and caches system totals; the service keeps its own protected `runtime/traffic.json`. Polls/reconnects/reloads do not duplicate totals; month rollover adds only new deltas (boundary resolution about one sample). Collection starts with this update and cannot reconstruct earlier traffic. System accounting requires updating the installed Windows service; old service versions remain connectable and show unavailable statistics. Counter errors must never prevent cleanup or trigger reconnects.

- Main UI: `outward_app/ui/main_window.py`. Below 760px of usable content width, settings stack vertically and connection actions move below status details; horizontal clipping is avoided with wrapped labels and viewport-driven layout changes.
- Window chrome: `ui/window_chrome.py` supplies `ChromeMainWindow` and a 32px palette-aware Qt title bar (icon/title and accessible minimize/maximize/close buttons). It preserves native Windows window styles via pointer-safe ctypes, non-client hit testing, native caption drag/double-click/system menu, resize edges and `HTMAXBUTTON` for Windows 11 Snap discovery. Maximized client bounds respect the monitor work area and an auto-hidden taskbar strip; no alpha window or region mask is used. Default Qt size is 903x682, with the previous 903x650 content area below the title bar; minimum is 900x592. Caption close uses the existing tray/asynchronous cleanup path. `tests/test_window_chrome.py` tests real HWND messages at 100/125/150% including negative screen coordinates; see `docs/validation/window-chrome.md` for limits of that verification.
- `outward_app/ui/widgets.py` provides `ElidedLabel` (full accessible text/tooltip, elided rendering), `StatusCaption` (empty captions collapse), and `CurrentPageStack` backed by `CurrentPageLayout`. Both size hints and layout-level height-for-width follow only the active tab. `MainWindow` starts with 903x650 of content plus its 32px title bar: home fits a row of cards without scrolling; additional rows and tall settings scroll inside their own areas, never the outer page. Verify on the native Windows Qt plugin as well as offscreen. `PlusButton` and `PlusBadge` paint centered plus strokes independently of font metrics. Settings dropdowns stay compact and the save action is a 36px primary button aligned right.
- `SwitchControl` keeps its custom painting but derives from `QCheckBox` for Tab/Space and native accessible role/state. Setting rows supply accessible names; checked tracks and focus use the active Graphite palette.
- Profiles have a visible three-dot action menu and an empty state with an add action. The profile dialog preserves five protocol pills with enabled/disabled availability and tooltips; a valid pasted link selects its protocol automatically, and invalid input receives inline validation. The resources dialog commits drafts on selection changes and Done, rejecting blank/duplicate entries.
- Progress and recovery details are visible when relevant; routine idle/connected captions collapse to retain the original compact header height. Disconnected protocol/name reflect the selected profile; an active session retains its own metadata when selection changes. Connection errors show sanitized details, recovery guidance and an Open Log action; embedded ss/vless URLs are redacted.
- Settings split «Автозапуск» (launch the app with Windows) from «Автоподключение» (a bounded, keyboard-accessible checklist of system/window connections, visible only while autostart is enabled). Each saved connection retains its own `auto_connect` choice while autostart is off; no selection means launch the app alone. Connections without an assigned profile are disabled in the list. Automatic connections run only after `--autostart` launch with `launch_on_startup` enabled. Legacy settings migrate the old toggle to the initial proxy window; an existing connection collection determines the initial launch setting from its choices, while an explicit new setting always wins.
- Profile dialog: `outward_app/ui/dialogs.py`.
- Qt standard dialog buttons follow `ui/i18n.py`'s active language through a QApplication-owned `QTranslator`. Russian loads bundled `assets/translations/qtbase_ru.qm` (PySide6's catalog for source runs); English removes it and uses Qt's source labels. `OutwardApp.spec` includes this catalog. Standard button roles and return values are preserved; tests exercise the real service confirmation and decline it without starting installation.
- Localization: `ui/i18n.py` provides Russian-source/English UI translations with parameters inserted after translation. `AppSettings.language` accepts `ru`/`en`, defaulting invalid/legacy values to Russian. General settings place a native single-select «Русский / English» dropdown below appearance. `JsonStore.save_language` atomically saves only language; it applies before window construction on the next launch, preserving sessions and unsaved form drafts when selected. The shared `ui/widgets.py` `SelectCombo` paints a theme-aware chevron and ignores wheel changes. User content and original engine diagnostics are preserved. `tests/test_language.py` covers storage, catalog format parameters, English startup, keyboard selection, rollback and layout.
- Appearance: `ui/themes.py` owns Graphite light/dark semantic palettes and a QApplication-owned ThemeManager; `ui/styles.py` generates QSS from them. QPalette, optional Fluent controls, painters, menus, native title bar and journal share the current theme. The General settings selector applies immediately and persists only `theme` through `JsonStore.save_theme`, without applying ports/startup or form drafts. Old/invalid values fall back to dark. General settings saves retain the field. Journal re-theming preserves selection/scroll; no windows/sessions are recreated. `tests/test_themes.py` covers persistence, errors, live state and plain-Qt fallback; `docs/validation/capture_graphite.py` captures synthetic native UI and checks both themes at 100/125/150%. Russian is the default UI language; English is available from the independent language selector.
- `MainWindow` owns settings/profiles and `SessionController`; `ui/connections.py` bridges session events to Qt. `connection_card.py` pins the system card and add action above a scrollable card list. `connection_dialog.py` assigns a profile and automatic/fixed ports. Browser/installation/system-log operations use a four-worker Python executor; a GUI-owned timer collects completed futures and dispatches callbacks, deduplicating outstanding jobs by key. Do not restore per-call QObject workers moved to QThreads: deleting a Python-backed QObject in the worker can wait for the GIL while holding a Qt signal mutex needed by the GUI during log rendering. Exit drains jobs before shutting down the executor. See `docs/validation/ui-freeze.md` for the captured live hang and native regression.
- Home and Settings are separate routes in a `CurrentPageStack`. Settings is opened from the sidebar button directly below New profile and contains the existing log/client settings/update tabs; a back action returns home. Route changes preserve sessions and unsaved settings. The log tab selects a session by stable ID; card diagnostics navigate there. Existing dialog behavior and font sizes are preserved.
- The system card includes protocol metadata and hides routine state words and the status dot. The power control retains tooltip/accessible state; captions and values are separate, including a distinct HTTPS caption for WireGuard. Windows service setup uses explicit Install/Update system VPN service wording with a role/UAC explanation; it is not a separate client. Existing installed services must be explicitly updated to receive new service-side readiness/health fixes; TCP ping/UI fixes work in the GUI without altering the IPC version.
- `UpdateCheckWorker` and `UpdateDownloadWorker` subclass `QThread` and override `run` without a worker event loop; the QThread objects stay owned/deleted by the GUI thread, avoiding worker-thread QObject destruction. Startup performs a silent background check; the settings button runs the same check manually. The auto-update toggle stores `auto_update_app` and downloads available installers in the background.

Connect flow:

1. Snapshot the connection/profile/settings and establish its cancellation generation.
2. Parse the profile and discover the physical upstream. Clean verified legacy sessions once only if enabled.
3. Proxy window: reserve its own ports, generate/check a private config, start an owned process and verify listeners plus HTTPS through that window. System: ask the authenticated service to generate/check TUN config, verify the OS selects OutwardVPN and probe HTTPS through it.
4. Publish connected only after the route check. Save actual ports/history; optionally open this window's resource/browser once.
5. Monitor process/route health; cancel stale work and reconnect the affected session on network change. Offline port reservations and browser markers prevent another window from inheriting an existing browser's traffic.

Disconnect stops only that session, first signaling CTRL_BREAK through a private hidden console and a creation-time-verified helper, then forcing termination if hung. Exit/update awaits cancellation and cleanup of all owned connections and background jobs, then explicitly quits QApplication; closing an already-hidden tray window alone does not terminate its event loop. Browser processes are not killed. A per-user single-instance socket prevents accidental second GUI ownership.

## Sing-box Config Assumptions

- Proxy windows use loopback `http` and `socks` inbounds. TUN has no user proxy listener and uses dual-stack addresses, auto/strict routes, mixed stack, local-route exclusions and DNS hijack. `build_sing_box_config` retains the legacy mixed inbound API for callers/tests.
- Route final is always `proxy`; there is also a `direct` outbound.
- VLESS and Shadowsocks use `outbounds` tagged `proxy`; WireGuard uses a modern `endpoints` entry tagged `proxy`.
- Session configs use sing-box 1.13.14 typed DNS servers. Bootstrap DNS uses its own direct dialer with explicit `bind_interface` when known, with no detour to the empty direct outbound (which fails at startup despite passing `check`). Configured user DNS goes through `proxy`. System mode rejects `local` DNS. Tests start actual generated proxy configs as well as checking syntax; real TUN remains separate acceptance.
- The UI labels HTTP and SOCKS5 as distinct local ports and opens browsers through the SOCKS5 port.

## Tests And Commands

- Core tests live in `tests/test_core.py`; focused Qt behavioral regressions live in `tests/test_ui.py`, including a separate hidden native Windows process checking default window height on every tab. UI tests use synthetic in-memory profiles and mock network/process/startup/update boundaries.
- Tests cover parsers/storage, migration/session races/port isolation, real Windows pipe transport, offscreen Qt/accessibility/layout and two actual sing-box processes against a local HTTP server. Real TUN/service installation is a separate acceptance step, not covered by mocks or `sing-box check`.
- Run tests with `.\.venv\Scripts\python.exe -m unittest discover -s tests`.
- Run syntax checks with `.\.venv\Scripts\python.exe -m compileall outward_app tests`.
- Run the app with `.\.venv\Scripts\python.exe -m outward_app`.
- Install bundled runtime dependencies with `.\install-deps.ps1`; it reads `SING_BOX_VERSION`, downloads the matching Windows amd64 sing-box release, and writes `bin/sing-box.exe`. The binary is intentionally ignored by Git.
- Build a release installer with `build-installer.bat`; it bumps patch version in `VERSION`. Build a check installer without changing `VERSION` with `build-installer-check.bat` (PowerShell equivalent: `.\build-installer.ps1 -NoVersionBump`). PyInstaller spec is `OutwardApp.spec`, Inno Setup script is under `installer/`, and installer output goes to `installer-output/Outward App Setup-<version>.exe`. The script ensures sing-box is installed, reads root `release-notes.md` by default, writes `.sha256` and `installer-output/release-notes-<version>.md`, and the built executable is `dist/Outward App.exe`.
- Silent update installation launches the downloaded Inno Setup installer with `/SILENT /NORESTART`; the installer has a `skipifnotsilent` run entry so the updated app starts again after a silent update.
- To build and commit a release, run the local `build-installer.bat` without arguments, or `.\build-installer.ps1 -CommitRelease`. The BAT wrapper is ignored and untracked; fresh clones use the PowerShell command. After a successful build, it stages all non-ignored changes and creates `Release v<version>` without pushing. Before changing VERSION it checks Git identity, branch, conflicts, version newer than HEAD:VERSION, and local tag collisions. Failed builds retain the selected VERSION; retry with `-NoVersionBump -CommitRelease` on the PowerShell script. PyInstaller and Inno Setup nonzero exits stop the build even if old artifacts exist.
- GitHub Actions workflow `.github/workflows/release.yml` publishes releases automatically on push to `master` when `VERSION` changes. It installs Python deps, Inno Setup, sing-box via `install-deps.ps1`, runs tests, builds with `-NoVersionBump`, and publishes `v<version>` with installer and `.sha256`. Manual publishing remains available with `.\build-installer.ps1 -NoVersionBump -PublishRelease` when `gh` is authenticated.

Prefer unit tests for parser, config generation, storage, and path/data behavior. Offscreen GUI tests cover compact/wide layouts, profile/session metadata, visible safe errors, keyboard/accessibility state, profile validation and resource editing. They do not replace native on-screen checks for Windows screen readers, monitor changes or real network sessions; verify those when relevant.
Packaging builds `OutwardVPNService.spec` (onedir, no Qt) before `OutwardApp.spec` and includes the service payload. Both EXEs expose a safe `--check-runtime` import/SSL smoke check; the GUI check uses offscreen Qt without loading user profiles. Building does not install the service. Verify real TUN/DNS/UDP/IPv6/routes, restart/sleep, privileges and uninstall in a dedicated Windows environment before release.

## Change Guidance

- Treat this as a Windows-first app. `subprocess.STARTUPINFO`, `CREATE_NO_WINDOW`, PowerShell `Win32_Process` queries, `taskkill`, `.exe` discovery, and Chrome/Edge paths are intentional.
- Do not launch the GUI, kill processes, or start external proxy/browser processes unless the user explicitly requests it or the task requires a runtime check.
- Keep profile/settings JSON compatibility in mind when changing models or storage.
- Never log or display raw Shadowsocks passwords, WireGuard private keys, or WireGuard preshared keys when reporting connection errors.
- If a change materially alters architecture, runtime files, connect flow, packaging, or user-visible capabilities, update this skill in the same task so future Codex runs do not rediscover stale behavior.
